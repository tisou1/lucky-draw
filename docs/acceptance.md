# 人工验收步骤

本清单用于浏览器与现场设备验收。自动验证覆盖核心数据逻辑，不替代 GPU、投影及视觉验收。

## 名单与图片

1. 通过 `http://localhost:5173` 打开，在“参与者”中下载导入模板。默认名单应为空，三个奖项模板已经存在。
2. 导入模板 CSV，检查 `0001` 等编号保留前导零；重复导入应提示跳过重复编号。
3. 导入包含多个工作表的 XLSX，切换工作表、映射列；含空姓名的行应展示原始行号及错误。
4. 对 GBK / GB18030 的 CSV 选择 GB18030 编码，检查中文没有乱码。
5. 上传 `0001.png`、`0002.jpg` 和无法匹配的 `unknown.webp`，检查两名参与者头像更新，并报告失败文件。
6. 手动添加、搜索、编辑和删除参与者，刷新后确认名单顺序与数据保存。无头像时显示默认头像。

## 舞台与抽奖

1. 导入 `public/demo/participants-1000.csv`（最多 1000 人），配置奖项总名额至少 20，每轮 8 人。
2. 抽奖舞台应显示 1000 人已就位；渲染卡片上限 300，待机时每 12 秒循环展示后续名单。
3. 切换球体与螺旋，检查卡片名称、头像、粒子和轨道没有异常；点击全屏再退出。
4. 点击开始后，球体加速；默认 5 秒后自动停止，先保存结果，再减速聚焦并揭晓 8 人，通过分页查看全部中奖者。舞台应显示当前停止方式和配置秒数。
5. 在舞台空白处使用空格开始／停止；在人数输入框、按钮或弹窗中操作，不能意外触发额外抽奖；长按空格不能多次保存。
6. 抽奖期间切到参与者、奖项和设置页面，写入控制应禁用；自动模式仍按时保存，完成揭晓后恢复可操作。
7. 默认关闭重复中奖开关，继续不同奖项抽奖，中奖者应从候选池排除。开启后可跨奖项中奖，同奖项仍不重复。
8. 本轮人数超过剩余名额或候选人数时，应提示并阻止开始；中奖后刷新，结果与历史记录不变。
9. 在滚动阶段刷新，应回到待机，且没有新增记录。记录已保存后刷新，应恢复相同结果。
10. 打开第二个同地址页面，第二个页面应只读。首个页面完成抽奖后，第二个同步记录；关闭首个页面并在第二个点击“获取操作权限”，应能继续操作。
11. 在“设置 → 抽奖停止方式”将自动时间改为 10 秒并保存，刷新后仍为 10 秒；时间到自动停止。提前点击停止或按空格，只应新增一条记录，旧计时不能影响下一轮。
12. 切换为手动停止并保存，开始后等待超过原配置时间，应持续滚动；点击停止或按空格后揭晓。0、61、非整数秒数应拒绝保存。

## 性能与降级

1. 使用现场投影设备运行 1000 人名单，观察开始、停止和揭晓是否流畅；视设备切换低画质，此时最多 120 张卡片且像素比为 1。
2. 将页面切到后台再返回，动画应暂停并平稳恢复，无明显时间跳跃。
3. 在设置中开启“使用 2D 卡片舞台”，完成完整抽奖，确认结果和规则一致。
4. 在禁用 WebGL 的浏览器环境中打开，自动显示 2D 卡片舞台；可完整抽奖。
5. 开启操作系统“减少动态效果”，舞台应停止持续旋转并减少庆祝动画。
6. 在手机窄屏下检查参与者管理、导入弹窗、奖项和设置能滚动操作，表格能横向滚动。

## 备份与重置

1. 配置参与者头像和奖品图片，完成至少两轮抽奖，导出 ZIP 备份和 CSV 中奖记录。
2. 清空中奖记录需二次确认；执行后名单、头像和奖项保留，名额恢复。
3. 重置整个活动需二次确认；执行后回到空名单和默认奖项。
4. 选择先前 ZIP，应先展示数据概况；确认后恢复名单、头像、奖品图片、规则和记录。
5. 选择损坏 ZIP、缺少图片的备份或不支持的版本，必须拒绝恢复，当前活动保持不变。
6. 在另一个浏览器恢复备份，确认可以继续抽奖。导出 CSV 中的中文应正常，编号列在 Excel 导入时选择文本类型。

## 本次自动验证

- `pnpm typecheck`：应用及 Vite / Vitest 配置类型检查。
- `pnpm test:core`：CSV / XLSX 导入、头像匹配、随机取样、状态机、事务、备份、操作锁。
- `pnpm build`：首次交付时检查 ExcelJS、fflate Worker 和 3D 延迟加载模块的浏览器生产打包兼容性。

2026-10-06 UI 改版已在独立 Chrome 中检查桌面 1440×900、手机 390×844、100 人演示名单、自动／手动停止、8 人中奖分页、2D 舞台及减少动态效果。浏览器检查未报告运行时错误，所检查页面无横向溢出。实际投影、1000 人现场帧率、全屏及完整人工清单仍需在目标设备验收。
